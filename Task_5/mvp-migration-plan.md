# Cutover-план миграции на MVP (Parallel run)

## Таблица этапов

| Этап | Описание действия | Ключевые задачи                                                                                                                                                                                                                                                                                                                                                            | Ответственные | Время/Сроки | Риски и меры по снижению                                                                                                                                                                                                                                                                            |
|------|-------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|---------------|-------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **1. Подготовка** | Развёртывание инфраструктуры, найм команды, проектирование, юридическая подготовка | 1. Найм фронтенд и бэкенд-разработчиков, тестировщика<br>2. Выбор российского облачного провайдера (с сертификацией 152-ФЗ)<br>3. Заключение DPA с провайдером<br>4. Проектирование доменов, RBAC/ABAC<br>5. Подготовка списков клиентов и валидация контактов<br>6. Разработка инструкций для персонала                                                                   | Техдир (найм, облако, DPA, архитектура)<br>Бизнес-аналитик (списки, контакты, инструкции)<br>Администратор сети (инфраструктура) | 2-3 недели  | **Риск:** Долгий поиск разработчиков => **Мера:** Начать найм сразу, параллельно с проектированием<br>**Риск:** Юридические ошибки => **Мера:** Привлечь внешнего консультанта по 152-ФЗ                                                                                                           |
| **2. Разработка MVP** | Создание порталов, БД, RBAC, уведомлений, скрипта сверки | 1. Разработка портала пациента (запись, просмотр расписания)<br>2. Разработка портала ресепшена (запись офлайн-пациентов, просмотр)<br>3. Реализация RBAC/ABAC<br>4. Интеграция с SMS/email-провайдерами (с fallback)<br>5. Разработка скрипта ежедневной сверки (портал <=> Excel)<br>6. Настройка шифрования БД и TLS, бекапов                                           | Разработчики (бэкенд + фронтенд)<br>Администратор сети (TLS, шифрование)<br>Техдир (контроль) | 6 недель    | **Риск:** В команде сейчас нет фронтендера, есть риск не найти его в ближайшее время => **Мера:** Упростить интерфейс, использовать готовый UI kit<br>**Риск:** Скрипт сверки работает с ошибками => **Мера:** Тестировать на синтетических данных до пилота                                       |
| **3. Тестирование** | Функциональное, нагрузочное, RBAC, юридическое тестирование | 1. Функциональное тестирование порталов<br>2. Нагрузочное тестирование (100+ одновременных пользователей)<br>3. Тестирование RBAC (пациент не видит чужих записей)<br>4. Тестирование скрипта сверки<br>5. Юридическая проверка на соответствие 152-ФЗ (согласия, логи, шифрование)<br>6. Тестирование уведомлений (SMS, email, fallback)                                  | Бизнес-аналитик (функциональное, RBAC)<br>Администратор сети (нагрузочное)<br>Внешний консультант (юридическое)<br>Разработчики (исправление ошибок) | 2–3 недели  | **Риск:** Обнаружены критические ошибки RBAC => **Мера:** Отдельный тест-кейс на RBAC, исправление до пилота<br>**Риск:** Юридические нарушения => **Мера:** Не запускать MVP без согласования с консультантом                                                                                     |
| **4. Пилотный запуск** | Все сотрудники переходят на портал, старым клиентам выдаются логины/пароли | 1. Все ресепшены и врачи начинают работать в портале (Excel - только резерв)<br>2. Выдача логинов/паролей старым клиентам (100–200 активных пациентов)<br>3. Пациенты видят расписание и могут записываться<br>4. Ежедневный запуск скрипта сверки<br>5. Сбор обратной связи от персонала и пациентов<br>6. Обучение персонала работе в портале (проводит бизнес-аналитик) | Бизнес-аналитик (обучение, сверка, обратная связь)<br>Ресепшен (выдача паролей)<br>Техдир + администратор сети (мониторинг) | 2 недели    | **Риск:** Портал падает под нагрузкой => **Мера:** Мониторинг 24/7, готовность к откату<br>**Риск:** Персонал не справляется с новым функционалом **Мера:** Ежедневные опросы персонала<br>**Риск:** Пациенты не понимают, как записаться => **Мера:** Простая инструкция в ЛК, поддержка ресепшена |
| **5. Полный запуск (параллельная работа)** | Портал используется для всех записей, Excel остаётся резервом | 1. Все пациенты (не только пилот) постепенно получают доступ в портал<br>2. Ресепшен записывает всех пациентов через портал<br>3. Excel не запрещён, но не используется (только как резерв)<br>4. Ежедневная сверка продолжается, расхождения анализируются и устраняются<br>5. Информирование персонала о предстоящем отключении Excel                                    | Техдир (контроль перехода)<br>Бизнес-аналитик (сверка)<br>Администратор сети (мониторинг) | 2–3 недели  | **Риск:** Накопление расхождений между порталом и Excel => **Мера:** Увеличить частоту сверки до 2 раз в день<br>**Риск:** Сбой портала => **Мера:** Активация плана отката (возврат на Excel)                                                                                                        |
| **6. Мониторинг и стабилизация** | Снижение расхождений до нуля, подготовка к отключению Excel | 1. Добиться нулевых расхождений между порталом и Excel<br>2. Сотрудники работают только в портале (Excel не используется)<br>3. Сбор метрик: число записей, доставляемость уведомлений, время отклика<br>4. Исправление выявленных ошибок (быстрые релизы)                                                                                                                 | Бизнес-аналитик (сверка, метрики)<br>Администратор сети (мониторинг)<br>Разработчики (исправления) | 2 недели    | **Риск:** Новые ошибки в портале => **Мера:** Быстрые релизы с исправлениями (CI/CD)                                                                                                  |
| **7. Отключение Excel** | Портал становится единственной системой записи | 1. Административное и техническое запрещение записи в Excel (закрыть доступ к файлам)<br>2. Остановка скрипта сверки<br>3. Excel-журналы оставить только для чтения (исторические данные)<br>4. Портал - единственный источник записи                                                                                                                                      | Техдир (решение)<br>Администратор сети (техническое закрытие доступа)<br>Бизнес-аналитик (контроль) | 1 день      | **Риск:** После отключения Excel обнаружен критический баг портала => **Мера:** План отката (вернуть Excel за 1 час)                                                                                                                                                                                 |
| **8. План отката (на любом этапе)** | Возврат к Excel при сбое новой системы | 1. Восстановить доступ к Excel-журналам<br>2. Выключить портал<br>3. Загрузить данные из портала за последние сутки в Excel (скриптом обратной сверки)<br>4. Уведомить персонал о возврате к Excel<br>5. После устранения проблемы - повторный запуск портала                                                                                                              | Администратор сети (технический откат)<br>Техдир (решение об откате)<br>Бизнес-аналитик (сверка данных) | 1–2 часа    | **Риск:** Потеря данных при откате => **Мера:** Скрипт обратной сверки должен быть готов до пилота<br>**Риск:** Долгое восстановление => **Мера:** Регулярные учения по откату (раз в 2 недели)                                                                                                       |

## Роли и ответственность

| Роль                       | Наличие в штате | Ключевые обязанности в cutover-плане                                                                        |
|----------------------------|-----------------|-------------------------------------------------------------------------------------------------------------|
| **Технический директор**   | Есть            | Найм разработчиков, выбор облака, DPA, общая архитектура, контроль, решение об откате                       |
| **Бизнес-аналитик**        | Есть     | Обучение персонала, подготовка списков клиентов, сверка данных, функциональное тестирование, обратная связь |
| **Администратор сети**     | Есть     | Облачная инфраструктура, TLS, шифрование, мониторинг, технический откат, бекапы                             |
| **Разработчик (бэкенд)**   | Нанять (1)      | API, БД, RBAC, уведомления, скрипт сверки                                                                   |
| **Разработчик (фронтенд)** | Нанять (1)      | Портал пациента, портал ресепшена, адаптивность                                                             |
| **Тестировщик** | Нанять (1)      | Тестирование                                                                                                |
| **Консультант по 152-ФЗ**  | Привлечь\нанять | Юридическая проверка, DPA, согласие на ПД                                                                   |

## Общая оценка сроков

| Этап | Длительность |
|------|--------------|
| Подготовка | 2-3 недели   |
| Разработка MVP | 6 недель     |
| Тестирование | 2–3 недели   |
| Пилотный запуск | 2 недели     |
| Полный запуск (параллельная работа) | 2–3 недели   |
| Мониторинг и стабилизация | 2 недели     |
| Отключение Excel | 1 день       |

**Итого:** ~16–20 недель (4–5 месяцев).
