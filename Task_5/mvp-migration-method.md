# Анализ текущей ситуации и выбор стратегии

### Существующая система:
- Запись пациентов осуществляется сотрудниками ресепшн в Excel-журналы
- Расписание врачей ведется в отдельных Excel-файлах
- Отсутствует единая БД пациентов
- Нет разграничения доступа (кроме доменной аутентификации)
- Нет автоматических уведомлений
- IT-штат - 3 человека

### Требования к новой архитектуре (MVP):
- Портал для самостоятельной записи пациентов
- Портал для ресепшена (просмотр записей + запись офлайн-пациентов)
- Автоматические напоминания о приёме
- Категоризация данных по доменам
- RBAC/ABAC для разграничения доступа
- Соответствие 152-ФЗ

### Бизнес-цели миграции:
- Запустить MVP через 2 месяца
- Не останавливать текущий бизнес
- Снизить риски утечки данных
- Обеспечить возможность масштабирования на новые филиалы

# Выбор стратегии миграции на MVP
Для миграции на MVP выбрана стратегия **Parallel Run** с временным разрешением двойной записи и ежедневной (полу-)автоматической сверкой. 
Этот подход обеспечит непрерывность бизнес-процессов при возможных сбоях новой системы и даст относительно простой путь отката. 

В процессе реализации MVP также будут использованы элементы **High-level design** - для выделения доменов и закладывания принципов Privacy by design в новую систему (разграничения доступа, например).
Подход Branch by abstraction может быть использован на следующих этапах миграции, например, при внедрении платежного шлюза.

### Преимущества подхода Parallel Run
- минимизация простоя бизнеса
- прозрачность для руководства (можно сравнить метрики)
- плавное обучение персонала
- возможность отката без потерь

### Ограничения подхода Parallel Run и их смягчение
| Ограничение |	Способ смягчения |
| :----------------- | :----------------------- |
| Двойная запись (Excel + портал) |	Разрешена временно (2–4 недели), пока новая система не стабилизируется |
| Рассинхрон данных |	Ежедневная автоматическая сверка (скрипт сравнивает записи, разрешает конфликты) |
| Дополнительная нагрузка на персонал	| Только на переходный период; после стабилизации - запрет записи в Excel |
| Конфликты на сверке | Возможно, потребуется полу-автоматический режим, с ручной валидацией |
